# PRD — 005-fix-future-debt-missing-card-delete

## Bug 1: missing_card_reference PERSISTS after spec 004 fix

### Title
Future debt installments still show "missing_card_reference" after re-import

### Problem Statement
All future debt installments show "missing_card_reference" even though spec 004 fixed the `groupKey` field. The root cause is that `CardInstallmentProjection.rowId` stores the **preview row's `id`** (e.g., 'g-1' or a UUID from the AI extraction preview), but at query time the lookup in `normalizeProjection()` uses `projection.rowId` to find `CardStatementRow.id`, which is a **different UUID** generated by the database at insert time. This means the row→projection join always fails for newly accepted statements.

### Expected Behavior
Each future debt installment should show the correct card reference (e.g., "Banco Galicia •••• 1234") and be grouped under that card in the UI, not appear in `pendientes` with "missing_card_reference".

### Screenshots / UI State
The user sees:
```
Cuota Agosto-2026 | missing_card_reference | $ 33.300,00
Cuota Agosto-2026 | missing_card_reference | $ 21.666,68
...
```

### What Should Happen
All rows should be associated with the card that was imported, displaying the card name/nickname and grouped correctly.

## Bug 2: Cannot delete erroneous records

### Title
Cannot delete erroneous card statement records

### Problem Statement
The user loaded a card statement with wrong data (e.g., wrong amounts, wrong dates, wrong card). They want to delete it entirely, but the UI has no delete option for accepted card statements. Only draft statements can be deleted via `DELETE /drafts/:draftId`.

### Expected Behavior
User should be able to delete an accepted card statement from the UI. The deletion should cascade to all related records (sections, groups, rows, projections, manual purchases).

### Screenshots / UI State
When viewing an accepted card statement, there is no delete button or option available.

### What Should Happen
The user should be able to select an accepted card statement and delete it, removing all associated data from the database.
